# 1. Record Architecture Decisions

Date: [YYYY-MM-DD]

## Status
Accepted

## Context
We need to record significant architectural and design decisions so that future maintainers and coding agents understand the rationale, trade-offs, and constraints.

## Decision
We will use Architecture Decision Records (ADRs) structured with Context, Decision, and Consequences.

## Consequences
- Decisions are documented close to the code.
- Historical context is preserved without bloating the primary `AGENTS.md` context.
